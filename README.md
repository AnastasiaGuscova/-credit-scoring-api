# Credit Scoring — система оценки кредитного риска

## 1. Описание проекта

**Credit Scoring** — прототип системы оценки кредитного риска заёмщика на основе алгоритмов машинного обучения.

Система анализирует характеристики кредитной заявки и оценивает вероятность того, что заёмщик относится к классу клиентов с неблагоприятным кредитным исходом (default).

Основная задача проекта — построить модель бинарной классификации, которая:
- оценивает риск дефолта по данным кредитной заявки;
- принимает решение о выдаче или отказе в кредите на основе заданного порога вероятности;
- объясняет результат с помощью метода SHAP;
- формирует понятное текстовое объяснение с использованием локальной языковой модели;
- при отказе ищет альтернативные варианты изменения заявки, при которых прогнозируемый риск может оказаться ниже установленного порога.

Проект объединяет классическое машинное обучение, интерпретируемый анализ предсказаний и генеративную языковую модель.

## 3. Датасет и целевая переменная

Для обучения используется **German Credit Dataset (credit-g)**, загружаемый из OpenML.

Датасет содержит 1000 объектов и 20 исходных признаков, описывающих кредитную историю и характеристики заёмщиков.

Целевая переменная — `class`:

- `0 — good`: заёмщик с благоприятным кредитным исходом;
- `1 — bad`: заёмщик с неблагоприятным кредитным исходом (default).

Таким образом, задача модели — бинарная классификация.

В проекте класс `1` рассматривается как положительный класс при оценке риска: чем выше предсказанная вероятность принадлежности к нему, тем выше оценка кредитного риска.

## 4. Архитектура и пайплайн проекта

Работа системы состоит из нескольких последовательных этапов.

### Этап 1. Загрузка и подготовка данных

Данные загружаются из OpenML. Далее выполняются:
- проверка структуры датасета;
- обработка пропусков;
- преобразование типов признаков;
- разделение числовых и категориальных признаков;
- создание дополнительных признаков (Feature Engineering).

В результате исходные 20 признаков преобразуются в 22 признака, используемых моделью.

Дополнительно создаются:

- `credit_amount_per_month_proxy` — производный признак, отражающий отношение суммы кредита к сроку;
- `age_group` — возрастная группа заёмщика.

### Этап 2. Разделение выборок

Данные разделяются на три части с сохранением пропорций классов (stratified split):

- 60% — обучающая выборка;
- 20% — валидационная выборка;
- 20% — тестовая выборка.

Валидационная выборка используется для выбора порога классификации, а тестовая — для итоговой оценки качества модели.

### Этап 3. Обучение модели

В качестве основного алгоритма используется **CatBoostClassifier**.

CatBoost — алгоритм градиентного бустинга над решающими деревьями, который поддерживает обработку категориальных признаков и позволяет моделировать нелинейные зависимости между характеристиками объектов.

Модель обучается на подготовленных данных и оценивает вероятность принадлежности заёмщика к классу `bad`.

В проекте не используется балансировка классов.

После обучения модель сохраняется в формате `.cbm`, а информация о выбранном пороге классификации — в отдельном JSON-файле.

### Этап 4. Выбор порога классификации

Стандартный порог 0.5 не используется. По результатам анализа на валидационной выборке выбран порог:

`CLASSIFICATION_THRESHOLD = 0.25`

Правило принятия решения:

- вероятность дефолта меньше 0.25 — заявка получает решение `approve`;
- вероятность дефолта больше или равна 0.25 — заявка получает решение `decline`.

Порог влияет на соотношение ошибок первого и второго рода. В частности, его снижение позволяет выявлять больше потенциально рискованных заёмщиков, но может увеличить количество отказов клиентам, которые в действительности не допустили бы дефолт.

### Этап 5. Интерпретация результата с помощью SHAP

Для объяснения предсказаний применяется SHAP (SHapley Additive exPlanations).

Метод позволяет оценить вклад каждого признака в конкретное предсказание модели.

Для каждой заявки система:
- получает SHAP-значения признаков;
- определяет направление влияния на прогноз;
- выбирает несколько наиболее значимых факторов;
- передаёт их для отображения в пользовательском интерфейсе.

Положительное SHAP-значение смещает предсказание в сторону класса `bad`, отрицательное — в сторону класса `good`.

SHAP объясняет поведение модели, но не устанавливает причинно-следственную связь между характеристикой заёмщика и дефолтом.

### Этап 6. Поиск альтернативных вариантов заявки

Если модель принимает решение `decline`, запускается дополнительный механизм поиска альтернативных вариантов (Counterfactual Explanation).

Он проверяет допустимые изменения отдельных параметров заявки и повторно рассчитывает вероятность дефолта.

В текущей реализации рассматриваются:
- уменьшение суммы кредита;
- изменение срока кредита.

Система ищет варианты, при которых прогнозируемая вероятность дефолта становится ниже порога 0.25, и выводит наиболее подходящие найденные сценарии.

Это не означает, что банк гарантированно одобрит изменённую заявку. Результат показывает только то, как изменится прогноз текущей модели при заданных параметрах.

### Этап 7. Генерация текстового объяснения

Для формирования понятного пользователю текста используется локальная языковая модель **Qwen 3.5 4B**, запускаемая через Ollama.

Языковая модель получает уже рассчитанные результаты:
- вероятность дефолта;
- порог классификации;
- принятое решение;
- наиболее значимые SHAP-факторы;
- найденные альтернативные сценарии.

LLM используется исключительно для преобразования технических результатов в естественный язык.

Она не принимает кредитное решение, не пересчитывает вероятность и не определяет самостоятельно, какие изменения заявки приведут к одобрению.

Если генерация не удалась или превысила установленное время ожидания, приложение использует резервное текстовое объяснение, сформированное программно.

## 5. Результаты обучения и качество модели

Итоговая модель CatBoostClassifier оценивалась на тестовой выборке из 200 объектов.

**Результаты на тестовой выборке:**

| Метрика | Значение |
|---|---:|
| ROC-AUC | 0.7882 |
| Precision | 0.4592 |
| Recall | 0.7500 |
| F1-score | 0.5696 |
| Accuracy | 0.6600 |

Дополнительно получена следующая матрица ошибок:

| | Предсказан good (0) | Предсказан bad (1) |
|---|---:|---:|
| Фактически good (0) | 87 | 53 |
| Фактически bad (1) | 15 | 45 |

### Интерпретация метрик

- **ROC-AUC = 0.7882** — модель демонстрирует способность различать заёмщиков двух классов. Чем ближе значение к 1, тем лучше разделение классов.
- **Precision = 0.4592** — среди объектов, отнесённых моделью к классу `bad`, около 45.92% действительно относятся к этому классу.
- **Recall = 0.7500** — модель обнаруживает 75% всех объектов класса `bad` в тестовой выборке.
- **F1-score = 0.5696** — гармоническое среднее Precision и Recall.
- **Accuracy = 0.6600** — доля правильных предсказаний среди всех тестовых объектов составляет 66%.

### Анализ матрицы ошибок

На тестовой выборке модель получила:

- 87 истинно отрицательных предсказаний (True Negative);
- 45 истинно положительных предсказаний (True Positive);
- 53 ложноположительных предсказания (False Positive);
- 15 ложноотрицательных предсказаний (False Negative).

Для кредитного скоринга особенно важно учитывать False Negative: это случаи, когда потенциально проблемный заёмщик ошибочно классифицируется как надёжный.

В текущей конфигурации модель обнаруживает 75% объектов класса `bad`, однако одновременно допускает достаточно большое количество ложноположительных отказов.

Это отражает выбранный компромисс между выявлением потенциально рискованных заёмщиков и количеством ошибочных отказов.

**Результаты на валидационной выборке:**

| Метрика | Значение |
|---|---:|
| ROC-AUC | 0.7442 |
| Precision | 0.4455 |
| Recall | 0.8167 |
| F1-score | 0.5765 |
| Accuracy | 0.6400 |

Порог 0.25 был выбран с учётом результатов на валидационной выборке. Итоговые метрики на тестовой выборке рассчитаны отдельно.

## 7. Запуск проекта

### Требования

- Python;
- установленная библиотека Ollama;
- загруженная модель `qwen3.5:4b`.

### Установка зависимостей

Создайте виртуальное окружение и установите необходимые библиотеки:

```bash
pip install -r requirements.txt
```

### Запуск Ollama

Убедитесь, что локальный сервер Ollama запущен и модель доступна:

```bash
ollama list
```

При необходимости загрузите модель:

```bash
ollama pull qwen3.5:4b
```

### Запуск веб-приложения

Из корневой директории проекта выполните:

```bash
python flask_app.py
```

После запуска приложение будет доступно по адресу:

```text
http://127.0.0.1:5000
```

Если файл обученной модели отсутствует, сначала необходимо выполнить обучение:

```bash
python train.py
```

## 8. Ограничения и дальнейшее развитие

Текущая версия проекта имеет ряд ограничений:

- Используется исторический German Credit Dataset, поэтому результаты нельзя напрямую переносить на современные банковские данные.
- Модель не проходила полноценную калибровку вероятностей.
- Выбранный порог классификации отражает компромисс между Precision и Recall и может не соответствовать требованиям реальной кредитной организации.
- SHAP показывает вклад признаков в предсказание модели, но не доказывает причинно-следственные связи.
- Контрфактический поиск ограничен заданным набором изменяемых признаков и диапазонами значений.
- Найденный альтернативный сценарий не гарантирует одобрение кредита реальным банком.
- Генеративная модель может допускать неточности в формулировках, поэтому ключевые числовые результаты и решения формируются программно.

Возможные направления развития:
- калибровка вероятностей;
- более глубокий анализ дисбаланса классов и подбор гиперпараметров;
- расширение набора реалистичных контрфактических сценариев;
- тестирование на дополнительных кредитных датасетах;
- добавление API-документации и автоматизированных тестов;
- мониторинг качества модели и анализ устойчивости предсказаний.
